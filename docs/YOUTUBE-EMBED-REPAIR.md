# YouTube embedding configuration and covers

BulkEmbed and YouTubeAPI have separate settings. The server-side BulkEmbed `API_KEY` was empty even though YouTubeAPI had its primary key configured. BulkEmbed is now configured with the owner's supplied key, after a private, verified off-VM settings backup. Native search requests run server-side; credentials are not committed or sent to frontend JavaScript. Provider quota is shared by the Google Cloud project and can still block bulk searches.

The reported single-video link saved as video 33, “Chill Hop”, with type `embed` and no artwork file. Native single embedding requests metadata from Encoder before saving artwork; that did not produce a saved thumbnail for this item. The existing DivineThumbnails hook only queued local video/audio sources, so it could not repair the missing embed cover.

DivineThumbnails 1.2 adds a narrowly scoped fallback after a new embed is saved: parse supported YouTube link forms and fetch the fixed `i.ytimg.com` thumbnail URL. No API key, video download, Encoder conversion, or replacement publishing path is involved. Existing covers are preserved. URLs are strictly parsed; remote requests verify TLS, disallow redirects, have a six-second timeout and a two-megabyte limit. JPEG data and storage boundaries are validated before atomic no-overwrite publication. Only the affected video's image/metadata cache is invalidated. Existing local video/audio queue and worker behavior remains unchanged.

Validation uses a standalone PHP contract test (`tests/backend/youtube-embed-cover.php`) with six supported link forms, eight unsafe/invalid inputs, existing-cover preservation, and storage boundary checks. Run `php tests/backend/youtube-embed-cover.php backend/divine-thumbnails/EmbedCover.php`. This test makes no network calls or database changes. The 19 Python backend tests also pass.

The live repair is limited to the reported embed's missing cover and the two plugin source files. Native publishing status is preserved. Private source backups and an exact before/after state report are retained on Azure; no container restart or broad cache flush is required. To roll back code, restore the privately backed-up original DivineThumbnails.php and remove only the added EmbedCover.php after verifying they still match this change. Preserve the recovered thumbnail unless explicitly reverting that repair.
